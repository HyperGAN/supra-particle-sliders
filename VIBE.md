# Native Supra vibe experiments

Install the optional collection add-on with `pip install '.[native,vibe]'`.
Set `NANOGPT_API_KEY` in the process environment using your private key source.
The key is read by the SDK and must not appear in command arguments or receipts.

```sh
supra-vibe --vibe 'a final boss confronting a small party of heroes' \
  --out runs/final-boss --rounds 4 --pool-size 2 --replace 1 --best-of 2
```

This command collects examples and writes a qualified manifest. Native rendering
uses Supra2-IMG at256²,50 positive Euler steps and CFG3 on CUDA. Native PNGs stay
unchanged. The effect judge sees a recorded whole-image512² LANCZOS presentation
because the NanoGPT decision route rejects images below280px per side. Its
four-level intended-effect score and equal-case ON−OFF fitness do not use beauty
or preservation scores. The proposer uses short paired contexts within the
native T5 limit. Completed calls and unknown pending calls retain the shared
collector's immutable recovery semantics.

`supra_pg0100_vibe` is a separate experimental native training binding. Its current
EMPF environment uses the captured core0.15 development/PG0.10 sources, HNDL0.10
and the verified HyperGAN builder. Installing the public product with its default
core0.13 dependency does not enable that environment. The existing public
fresh95 factory and historical data checks are unchanged.

The November17 run completed its declared128 updates using eight qualified
matched cases and800 completed native paired fields. FULL states preserve the
original initializer receipt, optimizer histories and RNG/counters. It uses raw
current weights, `ema_decay=None`, no particle bank and no CPU model forward or
backward. G0.036/D0.018 provisionally reuse the historical scoped reference; no
new EMPF/vibe optimum is claimed.

Equal-case intended-effect gains at32/64/96/128 are0.2254167,0.28,0.2733333 and
0.2670833. RAW64 is selected by that sole metric. All16 native OFF/ON images pass
the separate catastrophic-only check at every quarter. The strict public reader
reproduced the selected checkpoint's case0 native50-step latent exactly on a
fresh CUDA backbone, with zero official initializer calls or training updates.
All142 RAW tensor payloads match FULL64. A saved-state audit verifies every one
of128 FULL hashes and embedded steps, the original initializer receipt in each,
71 zero-UP payloads in FULL0, and128 actual regularizer calls (`lazy_k=1`).
These are eight training cases, not an unseen confirmation or released weights.

Actual host-floor failures and partial output work remain retained. Recovery
strictly loaded saved FULL states, reused completed conditioning/fields/outputs,
and never repeated a completed update prefix. The historical cohort is intact.

The RAW format is `Supra-native256-vibe-FP32-HNDL-v1`, with original named adapter
tensors and bound model/revision metadata. `supra_pg0100_vibe.inference.load_raw`
requires this native CUDA HNDL class, exact base identities, tensor schema and
RAW/no-EMA metadata. Its FP32 delta is cast to the native base output dtype.
Ordinary LoRA loading is not asserted to implement that arithmetic. Native
inference uses `sample_native(Backend(runtime), prompt, seed, strength=1.)` and
the original CUDA VAE. Cached-context runtimes reject prompts outside their
completed conditioning; `load_runtime` provides the original encoder/decoder
for new prompts when the declared CUDA resource budget fits.

All new work is separate from the historical PG0.9.5 cohort and completed LR
searches. Collection source, source closures, teacher hashes, normalization,
FULL/RAW states and actual resource failures are retained in the workspace
experiment ledger. No completed update or accepted judgment is replayed for
bookkeeping.
