# Shared ParticleGAN 0.9 integration

This derivative trains through the shared `ConditionalPG09` game. It supplies
native model loading, admitted asset checks, atomic checkpoint IO and command
line arguments. Losses, regularizers, optimizers, conditioning, balanced sampling
and both RNG streams belong to the shared package. It adds no optimized MSE
term. The native teacher cache is supervision data, not an MSE objective.

The checked-in source lock identifies the installed shared package's executable
sources. The public namespaces are `particle_sliders.pg09_remaining_campaigns`,
`particle_sliders.pg09_moss_campaign`, `particle_sliders.pg09_backends` and
`particle_sliders.supra_model`; `particle_sliders.pg09` owns the game. No
implementation is copied into this product. The packaging proposal introduces
new source lineage. Its final commit and wheel must be frozen by the shared
packaging owner and reviewed through Ada before this derivative is mergeable.

## Source and dependencies

Install `requirements.txt` with a suitable PyTorch build and the exact reviewed
shared wheel. An optional `PARTICLE_SLIDERS_ROOT` can point to a separate
checkout at the commit in [`shared.lock.json`](../shared.lock.json), or to its
package source directory. Installed wheels require no research checkout. All
executable shared sources are checksum validated. A previously imported shadow
package is rejected. The old vendored architecture is removed. No active
training checkout needs editing.

The public package proposal uses `particlegan==0.9.1`. Its shared game verifies the
installed released source profile as well as the version. PG 0.10 is rejected.
The earlier 0.9.0 CPU receipts remain separate evidence. They do not qualify
this new package/runtime cohort or permit rebinding old checkpoints.
The 104.1M native DiT, its LoRA target names, base/T5/VAE revisions and ordinary
adapter format remain compatible with the historical release.

## Context, time and conditioning contract

The exact config has **19 unique contexts including the stored unconditional**:
12 training captions, three preservation captions, bridge neutral/positive and
one fruit control. The two repeated verification subjects reuse training text.
The native runtime therefore performs 18 new T5 forwards when its stored empty
context is present. Context export checks the exact canonical config digest
`d32639ad9084f60d13faea1ef0e4d92b4bfc2e0420bc0fd15f4992c6270edd5b`,
model/T5 pins and budget before constructing a runtime or writing output.
No training step may encode a new prompt.

Supra's model input is native flow time `t` in `[0,1]`. The DiT timestep embedding
applies its internal factor of 1000. The Euler loop passes `i/steps` unchanged
and advances `z += velocity/steps`: noise at zero, data at one. There is no
descending sigma schedule or extra factor of 1000 at the product boundary.

The shared student uses neutral T5 conditioning, a frozen empty CFG branch,
and the frozen positive-prompt CFG velocity as target. Native signed strengths
operate on the conditional adapter branch; negative scales do not invert Euler
time. The shared provider retains native 4D velocity fields, pooled masked T5
features, time and path/preservation flags, with balanced sampling and the
reviewed preservation mixture. The real cache response scale must match the
shared reviewed constant; a synthetic CPU fixture is not a live cache.

## Owner-admitted execution

Only coordinator `01a147d7-f540-778e-ad79-4d8eb267403d` admits GPU work. These
commands document the worker seam; this audit has not run them on native GPUs.
They default to local cached weights and do not download models.

```bash
python scripts/prepare_pg09_contexts.py --shared-root "$PARTICLE_SLIDERS_ROOT" \
  --out /new/admitted/contexts.safetensors

python scripts/train_pg09.py --shared-root "$PARTICLE_SLIDERS_ROOT" \
  --cache /owner/admitted/teacher_cache.pt --cache-sha256 "$CACHE_SHA" \
  --contexts /new/admitted/contexts.safetensors --contexts-sha256 "$CONTEXT_SHA" \
  --frozen-base-sha256 "$FROZEN_BASE_SHA" --out /new/run \
  --steps 28800 --stop-at 80
```

The base digest covers each frozen parameter and buffer. Context receipts bind
the runtime source, config, stored unconditional, revisions and tensor hashes.
Training checks native teacher/cache parity across every subject, trajectory
role and preservation prompt before updating. Every checkpoint rechecks frozen
weights. Neither verification captions nor final heldouts supply training rows.

`--steps` is the unchanged maximum recipe budget. `--stop-at` is an absolute
pause point inside that budget. Resume with the identical recipe and
`--resume /new/run/step-000080`, selecting a later pause point. Full checkpoints
bind source/config/cache/context/base identities and restore adapter, critic,
both optimizers, native model RNG, sampler RNG, row order/cursor and exposure
counts through the shared loader. They are CPU-mapped and checksummed before
loading. An adapter-only export is for inference and cannot resume training.
Historical MSE checkpoints cannot resume as a shared GAN. Package promotion
changes source lineage and requires a new cohort or explicitly reviewed migration.

```bash
python scripts/infer_supra.py --shared-root "$PARTICLE_SLIDERS_ROOT" \
  --adapter /new/run/step-000080/adapter.safetensors \
  --prompt "An armored knight holding a sword in a ruined cathedral, full body, game concept art." \
  --scale 1 --out /new/preview.png
```

New exports declare `training_objective=pg09_gan_only`, the source lock, and
`cfg_adapter_branch=conditional_only`; native inference executes the same shared
response/CFG renderer. Legacy adapters without a branch marker retain both-
branch adaptation. Closed-form rank compression propagates that policy and
source marker. It does not silently reinterpret historical release weights.

## CPU evidence and outstanding gates

The tests execute a small real Supra DiT and ordinary LoRA on CPU. They forbid
MSE calls while checking shared GAN updates, changed adapter and critic, exact
frozen weights, checksum rejection and fresh-runtime full-state replay of the
next metrics and sampler exposures. Runtime tests cover negative/zero/fractional
strengths and CFG, the native timestep, metadata compatibility and atomic
malformed-adapter rejection. Context tests reject a twentieth prompt or a
same-count modified config before native load/output.

Before native admission, the packaging owner must provide the exact installable
reviewed head and the derivative must be re-pinned and wheel-tested. Remaining
GPU gates are pristine native base/teacher parity, actual frozen context export,
zero/no-grad/frozen-base checks, native adapter export/reload, fresh-process
full-state next-step replay, and signed image/control validation. No new training
quality, convergence, runtime performance or model publication is claimed here.
