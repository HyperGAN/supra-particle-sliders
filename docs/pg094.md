# Canonical PG0.9.4 Supra integration

As of 2026-11-04 the ordinary root package is `supra-particle-sliders==0.3.0`,
requiring Python >=3.11. It pins shared core 0.12.0 to immutable commit
`ddb41423bcefc1fe76cd94d0f9b367353b3ea137`, which includes the newly merged
isolated training dispatcher. The core requires `torch>=2.6,<3` and official
`particlegan==0.9.4` (upstream source `330eb94ee748cdcad131b0275d8de75fd5a7f96f`).
It imports the upstream losses, optimizer policy, regularizers and recipe;
this product owns native assets and orchestration, not a substitute GAN law.

The actual generator arm remains adapter GAN with `particles=None`, batch4,
native `[1,4,32,32]` continuous response fields and ordinary linear LoRA. The
separate HNDL profile retains the same arm and its own graph/source identity.
Neither is described as routed particles. No recipe, pretrained model revision,
FinalBoss MSE checkpoint or published weight is converted or retrained here.

## Install and validate

Use a fresh environment; the same distribution/namespace replaces earlier
cohorts and must not be installed over a checkpoint reproduction environment.
Install an appropriate CPU/CUDA PyTorch build, then:

```bash
python -m pip install -r requirements.txt
# Native loading requires the explicit native dependencies and staged assets:
python -m pip install '.[native]'
particle-slider profiles
python -m supra.train --help
```

The packaged recursive receipt `supra/core012-ddb4142-receipt.json` records all
574 tracked core source/data files, including relocated namespaces and nested
data. Both expected bytes and the complete non-cache file set are checked at
the imported core path. Core/PG versions and official PG source hashes are
checked before native admission. These are file/provenance checks, not executed
bytecode attestation or protection against concurrent mutation.

## Native inputs and training

Prepare the exact reviewed YAML campaign, 19 frozen contexts (including stored
unconditional), teacher cache and frozen-base SHA before training. Context
export uses the relocated product-owned native model and cache definitions:

```bash
python scripts/prepare_pg09_contexts.py --config configs/supra/prompts-final-boss.yaml --out /staged/contexts.safetensors --device cuda:0
```

The above performs native preparation and requires its existing qualification
and resource admission. It was not run by this upgrade. Do not substitute tiny
CPU fixtures for a real cache or claim they prove native quality.

Create a JSON session with exactly `backend`, `cohort` and `options`. Use backend
`supra`, a fresh explicit cohort name and the same options as the native API:
`native_config` (the parsed reviewed campaign object), absolute local `cache`
and `contexts` paths, their lowercase SHA256 values, `frozen_base_sha256`,
explicit `device="cuda:N"`, `rank=16`, `steps<=28800`, `batch=4`, `seed`,
`critic_width`, `base_precision="float32"` and optional `ema_decay`.
A config shape is provided in `configs/supra/session-pg094.example.json`; replace
its placeholders and campaign object with real admitted data before checking.

```bash
particle-slider plan --profile supra --config /staged/session.json --no-reporting
particle-slider train --profile supra --config /staged/session.json --check --no-reporting
particle-slider train --profile supra --config /staged/session.json --out runs/current --checkpoint-every 80 --export-format both --no-reporting
particle-slider train --profile supra --config /staged/session.json --out runs/resumed --resume /absolute/runs/current/artifacts/checkpoints/step-000080 --no-reporting
```

`python -m supra.train`, `scripts/train_pg09.py`, `scripts/train_lora_supra.py`
and the installed `particle-slider` use the current shared dispatcher. Product
entry points accept the shared session JSON flags; the old per-asset command
line belongs to `scripts/train_pg091_legacy.py` and the original PG0.9.1 source
environment. Output must be new/empty. Resume keeps the original fixed target
budget and refuses mismatched source/cohort/native identity. `--check` verifies
configuration, local checksums and source admission without loading the model;
it does not prove cache teacher parity or GPU compatibility. The profile is
explicitly `source_only`, with CPU software conformance only.

The existing native gates remain: CPU requires an explicitly staged software
fixture, production requires CUDA, FP32 parameter storage, exact native/T5/VAE
revisions, source-bound contexts, native teacher parity, and finite native
response fields. Native GPU fit, pretrained cache parity, 256px decoding,
convergence and image quality remain unrun. No weights are downloaded here.
